# API Test Authentication Pattern - NEW (January 2026)

## Summary

**PROBLEM SOLVED**: API tests were failing with 401 Unauthorized because:

1. Tests weren't getting valid auth tokens
2. `createTestRequest` didn't support `authToken` parameter
3. `createTestAuthUser` didn't return credentials for sign-in

**SOLUTION**: New helper functions that make authenticated API testing simple and reliable.

## Usage Pattern (RECOMMENDED)

### Step 1: Create Test Users in `beforeAll`

```typescript
describe('API: /api/my-route', () => {
  let supabase: SupabaseClient
  let adminUser: Awaited<ReturnType<typeof createTestAuthUser>>
  let vetUser: Awaited<ReturnType<typeof createTestAuthUser>>
  let ownerUser: Awaited<ReturnType<typeof createTestAuthUser>>

  beforeAll(async () => {
    supabase = await setupIntegrationTest()

    // Create users once, reuse across tests
    adminUser = await createTestAuthUser(supabase, 'admin', TEST_TENANT_ID)
    vetUser = await createTestAuthUser(supabase, 'vet', TEST_TENANT_ID)
    ownerUser = await createTestAuthUser(supabase, 'owner', TEST_TENANT_ID)
  })

  afterAll(async () => {
    await cleanupIntegrationTest()
  })

  afterEach(async () => {
    await cleanupManager.cleanupWithRetry()
  })

  // ... tests here
})
```

### Step 2: Get Auth Token in Each Test

```typescript
it('admin can create resource', async () => {
  // Get token (simple one-liner!)
  const authToken = await getAuthTokenFromUser(adminUser)

  const request = createTestRequest('http://localhost:3000/api/my-route', {
    method: 'POST',
    body: { name: 'Test Resource' },
    authToken, // ← Pass token here
  })

  const response = await POST(request)
  await expectSuccess(response)
})
```

### Step 3: Test Different Roles

```typescript
it('vet can access endpoint', async () => {
  const authToken = await getAuthTokenFromUser(vetUser)
  const request = createTestRequest(url, { authToken })
  // ...
})

it('owner cannot access admin endpoint', async () => {
  const authToken = await getAuthTokenFromUser(ownerUser)
  const request = createTestRequest(url, { authToken })
  const response = await POST(request)
  await expectError(response, 403) // Expect forbidden
})
```

## OLD Pattern (DO NOT USE)

```typescript
// ❌ OLD: Wrong password, wrong email format
await supabase.auth.signInWithPassword({
  email: `admin-${adminUserId}@test.local`, // ❌ Wrong email format
  password: 'testpass123', // ❌ Wrong password
})
const {
  data: { session },
} = await supabase.auth.getSession()
const authToken = session?.access_token || ''
```

**WHY IT FAILED**:

- Email format generated by `createTestAuthUser` is `${role}-${random_uuid}@test.local`
- Password is always `test-password-123`, not `testpass123`
- Tests were trying to use `userId` in email, but `userId` isn't in the email

## Rate Limiting Considerations

**IMPORTANT**: Supabase Auth has rate limits. To avoid hitting them:

### ✅ DO:

- Create users ONCE in `beforeAll` → Reuse across tests
- Call `getAuthTokenFromUser()` ONCE per test (not multiple times)
- Share tokens within a single test when possible

### ❌ DON'T:

- Create new users in every test
- Call `getAuthTokenFromUser()` multiple times unnecessarily
- Create auth clients without reusing them

### Rate Limit Errors:

```
Error: [Integration Test] Failed to get auth token: Request rate limit reached
```

**FIX**: Wait a few minutes, or reduce parallel test execution.

## Questions?

**Q: Why do I get "Request rate limit reached"?**
**A**: You're creating too many auth clients or signing in too frequently. Create users once in `beforeAll`, reuse tokens within tests.

**Q: Can I use different passwords?**
**A**: No. All test users use the standard password `test-password-123` for simplicity.

**Q: Do I need to clean up auth tokens?**
**A**: No. Tokens are ephemeral and auto-expire. `cleanupIntegrationTest()` handles user cleanup.

**Q: Can I share tokens across test files?**
**A**: No. Each test file should create its own users in `beforeAll`. Parallel test execution requires isolation.
